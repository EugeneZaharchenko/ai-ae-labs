# AG-UI чат у браузері — Go-міст до ADK-агента

Мінімальний вебчат: `go run` піднімає HTTP-сервер, який віддає одну вбудовану
HTML-сторінку (`go:embed`, без збірки й без Node), а сторінка спілкується з
агентом **протоколом AG-UI**.

> **Стан:** перевірено наскрізно — сторінка в браузері, події AG-UI від
> справжнього ADK-агента, образ `FROM scratch`, коректний drain (01.10.2026,
> macOS arm64, Docker 29.4.0, `adk/v2 v2.5.0`). Див. «Що саме перевірено».

## Навіщо AG-UI, а не CopilotKit

[AG-UI](https://github.com/ag-ui-protocol/ag-ui) — відкритий протокол
«агент ↔ інтерфейс». Він народився з
[CopilotKit](https://docs.copilotkit.ai/generative-ui/your-components/display-only),
і CopilotKit лишається його головним фронтендом. Важлива деталь: **CopilotKit
вимагає React і Node-рантайм**, а AG-UI — ні. Це той самий шар передачі подій,
і фронтенд лише мусить його розуміти.

Цей демо бере AG-UI без Node, бо репозиторій курсу — Go і Markdown
(AGENTS.md §5). Плюс це має практичний сенс: `go build` дає один статичний
бінарник із вбудованою сторінкою, а не `package.json` на 300 МБ.

Wire-формат ідентичний, тож React-фронтенд CopilotKit можна буде навести на
`/agui` пізніше — без правок у `main.go`. Форма подій у цьому демо перевірена
збіркою SSE через офіційний Go SDK, тому вона не «схожа на AG-UI», а ним і є.

## Що потрібно

Жодних ключів. Агент — це граф функцій (той самий, що в лабі Дня 4), у ньому
немає жодного LLM-вузла, і сервіс сам це логує: *«no model credentials
required»*. Потрібні `curl` і Docker (для контейнерного шляху).

## Локально: два процеси

Агент лишається окремим сервісом — міст його не містить, а лише викликає.

```bash
# термінал 1 — агент на :8080 (та сама лаба Дня 4)
task week2:day4:serve

# термінал 2 — міст і сторінка на :8081
task demo:agui:serve
# → http://127.0.0.1:8081/
```

Порт мосту окремий від `PORT` агента навмисно:

```bash
task demo:agui:serve:port BRIDGE_PORT=8090
```

## Контейнер: один образ, два процеси

`FROM scratch`, non-root `65532:65532`. Агент запускається **як дочірній
процес мосту** — у `scratch` немає `/bin/sh`, тож скрипт-обгортка там
неможлива, і супервізор живе в Go (`AGENT_BIN`).

```bash
task demo:agui:image        # docker build -f demo/agui_web/Dockerfile -t ai-ae-agui:demo .
task demo:agui:run          # --read-only --cap-drop ALL, публікується лише сторінка
task demo:agui:smoke        # наскрізна перевірка: події AG-UI від агента
task demo:agui:stop         # SIGTERM + доказ drain обох процесів (exit=0)
task demo:agui:verify       # розмір/користувач + перевірка, що apps/.env не в образі
task demo:agui:rm
```

| Змінна | Типове | Навіщо |
|---|---|---|
| `PORT` | `8090` | порт на хості; `:8081` усередині контейнера |
| `BRIDGE_PORT` | `8081` | порт мосту всередині; у контейнері його задає образ |
| `AGENT_URL` | `http://127.0.0.1:8080` | де живе агент |
| `AGENT_BIN` | — | заданий → міст сам стартує цей бінарник (режим контейнера) |

Образ: **9 051 781 байт** (виміряно). Тому публікується лише сторінка: агент
доступний виключно через міст, а не як окремий відкритий порт.

## Як це працює

```
браузер ──POST /agui──▶ міст ──POST /api/run_sse──▶ ADK-агент
   ▲                      │                            │
   └──SSE: AG-UI events───┘◀───SSE: ADK node events────┘
```

| Частина | Роль |
|---|---|
| `web/index.html` | уся сторінка: стилі, розмітка, розбір SSE. Без фреймворків і без збірки |
| `aguiHandler` | приймає `RunAgentInput`, створює ADK-сесію, відкриває потік AG-UI |
| `translator` | перекладає вихід вузлів графа в події AG-UI — ядро демо |
| `streamAgent` / `parseSSE` | читає SSE від ADK (кадри через порожній рядок) |
| `startAgent` | супервізор дочірнього агента; `SIGTERM` → drain → `exit 0` |

### Переклад подій — найцікавіше

Граф Дня 4 видає по одному виходу на вузол. Міст розрізняє їх за формою:

| Вихід вузла | Подія AG-UI | Що бачить користувач |
|---|---|---|
| рядок (`"Кейс rc-1: статус pending"`) | `TEXT_MESSAGE_*` | звичайна відповідь у чаті |
| об'єкт (`{"case_id":"rc-1",…}`) | `TOOL_CALL_*` | **картка** з полів об'єкта |

Другий рядок — це та сама ідея, що в CopilotKit `useComponent`: агент вирішує,
що показати, а сторінка — як це намалювати. Тут `prepare` і `open_refund_case`
перетворюються на дві картки, і жодного рядка React для цього не потрібно.

## Що саме перевірено

Один запит `"Мерчант A-114 просить повернення по транзакції txn-2026-07-118845"`
дав таку послідовність (перевірено і локально, і з контейнера):

```
RUN_STARTED
TOOL_CALL_START: prepare        + ARGS + END + RESULT
TOOL_CALL_START: open_refund_case + ARGS + END + RESULT
TEXT_MESSAGE_START
TEXT_MESSAGE_CONTENT: "Кейс rc-txn-2026-07-118845-A-114: … статус pending"
TEXT_MESSAGE_END
RUN_FINISHED
```

У браузері це дві картки (`prepare`, `open_refund_case`) і одна відповідь.
Повторний запит на тому ж `threadId` дає `already_open` — сесія ADK справді
перевикористовується.

```bash
go test -race ./demo/agui_web/        # 76 випадків, без мережі й без агента
sh ./scripts/covgate.sh 85 demo/agui_web   # ok 100.0%
```

Тести перевіряють саме переклад подій (він і є логіка цього демо) і розбір
кадрів SSE.

## Три помилки, які тут уже виправлені

Демо перевірявся запуском, а не читанням коду, і три дефекти знайшлися саме так:

1. **`RUN_ERROR` замість тихого закриття.** Коли потік уже почався, HTTP-код
   надіслано; помилка мусить іти подією, інакше сторінка бачить порожню
   відповідь без причини.
2. **`JSON`-рядок декодується.** `output` приходить сирими байтами, тож рядок
   треба розкодувати — інакше у чаті видно `\"Кейс …\"` з екранованими лапками.
3. **`TOOL_CALL_RESULT` іде одразу після свого виклику.** Результат, що
   відстає від наступного виклику, робить потік невалідним, а інструмент
   виглядає як «все ще працює».

Плюс окремо: сторінка мала помилку, яку видно лише в браузері — контекст
потоку створювався заново на кожну подію, тож картки не малювалися взагалі.
`go test` цього не ловить; ловить `evaluate_script` у справжній вкладці.

## Межі демо

- **Немає LLM.** Агент — граф функцій, тож ключі не потрібні. Щоб побачити
  модель, замініть агента на `labs3` (`-mode=live`) і передайте `AGENT_URL`.
- **Один користувач.** Логіна немає, `userId` фіксований (`learner`);
  розмови розрізняються лише `threadId`, який стає id сесії ADK.
- **Немає HITL.** Паузи й запити підтвердження (`AGUIToolset` у CopilotKit) не
  реалізовані: граф Дня 4 не має точок зупинки.
- **Модуль без тегів.** Go SDK AG-UI ставиться як
  `v0.0.0-20261001154531-…`, тобто pseudo-version із `main`. Це community-SDK
  (офіційні — TypeScript і Python), і API може змінитися; саме тому версія
  зафіксована в `go.mod`.
- **Немає `zoneinfo`** в образі: на відміну від демо №6, тут ніщо не викликає
  `time.LoadLocation`.
