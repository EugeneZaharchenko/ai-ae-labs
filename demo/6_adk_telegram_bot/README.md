# 6 · ADK-агент у Telegram

Один `main.go`: Google ADK Go v2 агент, до якого ви пишете з Telegram. Бот сам
довгоопитує Bot API, віддає кожне повідомлення агенту й повертає відповідь.
Провайдер і модель беруться з `apps/.env` через `internal/modelcfg` — у коді
нічого налаштовувати не треба.

> **Стан:** перевірено збіркою, `go vet`, тестами з `-race`, `go run . -dry-run`
> і збіркою контейнера проти `apps/.env` (2026-10-01, macOS arm64, OrbStack
> 29.4.0, `adk/v2 v2.5.0`). Живе опитування Telegram **не спостерігалося**: у
> `apps/.env` цього чекауту немає `TELEGRAM_BOT_API`, тож шлях «повідомлення →
> відповідь» перевірений підставним сервером (`httptest`), а не реальним ботом.
> З контейнера підтверджено лише те, що не потребує токена: вихід у
> `api.telegram.org` дістає **401** (отже TLS і CA на місці) і `current_time`
> бачить `Europe/Kyiv`. Перший живий запуск — це `go run .` або
> `task demo:6_tg:image:run` після того, як ви додасте токен.

## Що потрібно

| Що | Навіщо |
|---|---|
| `TELEGRAM_BOT_API` в `apps/.env` | токен від [@BotFather](https://t.me/BotFather). Це пароль: хто його має, керує ботом |
| `TELEGRAM_ALLOW_USER_IDS` в `apps/.env` | список числових id через кому — це **контроль доступу** |
| ключ провайдера в `apps/.env` | той самий, що в лабах тижня 2 (`MODEL`, `DEFAULT_MODEL_PROVIDER`) |

Свій id дізнайтесь у [@userinfobot](https://t.me/userinfobot) — ім'я
користувача не є id.

Порожній `TELEGRAM_ALLOW_USER_IDS` — це не «усі», а відмова стартувати: бот із
платною моделлю, відкритий для будь-кого, витрачає ваш ключ. Якщо вам справді
потрібен відкритий бот, скажіть це прямо: `-allow-all`.

## Швидкий старт

```bash
# 1) перевірити ключі, провайдера й агента, не підключаючись до Telegram
cd demo/6_adk_telegram_bot && go run . -dry-run

# 2) запустити опитування Telegram (Ctrl-C — зупинити)
go run .

# 3) якщо увімкнено allowlist, а ви пишете з чужого акаунта, бот відмовить і
#    назве id, який треба додати в apps/.env
```

Файл `.env` шукається вгору від робочої теки, тож
`go run ./demo/6_adk_telegram_bot` з кореня репозиторію працює так само.

## Команди бота

| Команда | Дія |
|---|---|
| будь-який текст | агент відповідає; одна ADK-сесія на чат, тож контекст зберігається |
| `/new` | почати нову розмову (стара лишається на сервері, її id змінюється) |
| `/id` | показати ваш числовий id |
| `/help` | що вміє бот |
| `/start` | те саме, що `/help`, плюс ваш id |

## Що всередині

| Частина | Роль |
|---|---|
| `loadConfig` | читає токен і allowlist з оточення; друкарська помилка в id зупиняє старт |
| `newAgent` | один `llmagent` з інструментом `current_time` — щоб було видно, що виклик інструмента справді доїхав |
| `bot` | мінімальний клієнт Bot API: `getMe`, `getUpdates`, `sendMessage`, `sendChatAction`; 429 обробляється за `retry_after` від Telegram |
| `handler` | авторизація, команди, один хід агента, розбиття довгої відповіді на частини |
| `poll` | цикл довгого опитування; невдале опитування не вбиває бота, а повторюється через паузу |

Сесії зберігаються в пам'яті процесу: перезапуск бота починає нові розмови.
Історія повідомлень Telegram не зберігається ніде — бот працює лише з тим, що
йому надіслали після старту.

## Тести

```bash
go test -race ./demo/6_adk_telegram_bot/     # без ключів і без мережі
sh ./scripts/covgate.sh 85 demo/6_adk        # гейт покриття
```

Тести піднімають підставний сервер Telegram (`httptest`) і скриптовану модель
(`internal/fakellm`), тож перевіряють allowlist, команди, обробку помилок і
розбиття довгих повідомлень офлайн. Один тест, `TestNewAgentWiresTheTool`,
будує справжнього агента ADK і доводить, що `current_time` викликається.

## Docker: статичний образ, non-root, `FROM scratch`

**Контекст збірки — корінь репозиторію**, не ця тека: бот імпортує
`internal/modelcfg`, `internal/adkenv` і `internal/labrun` з кореневого модуля.
Тому `-f` вказує на Dockerfile явно.

```bash
task demo:6_tg:image           # docker build -f demo/6_adk_telegram_bot/Dockerfile -t ai-ae-telegram-bot:demo6 .
task demo:6_tg:image:inspect   # розмір, користувач, точка входу
task demo:6_tg:image:verify    # бінарник і zoneinfo на місці, apps/.env — ні
```

Запуск. Ключі передаються контейнеру, а не збираються в образ:

```bash
# нічого не питаючи в Telegram — тільки провайдер і агент
task demo:6_tg:image:dry

# справжній запуск: --env-file дає ключі, решта — гігієна контейнера
docker run --rm --name ai-ae-telegram-bot \
  --read-only --cap-drop ALL \
  --env-file apps/.env ai-ae-telegram-bot:demo6
```

| Що | Значення |
|---|---|
| Базовий образ | `scratch` — ні shell, ні пакетного менеджера, ні libc, нічого патчити |
| Користувач | `65532:65532` (у `scratch` немає `/etc/passwd`, тож лише числова форма) |
| Розмір | **13 397 837 байт** (виміряно 2026-10-01, `linux/arm64`, OrbStack 29.4.0) |
| Шари | 4 |
| `EXPOSE` | немає — бот довгоопитує Telegram і нічого не слухає |
| `STOPSIGNAL` | `SIGTERM` — саме його чекає `signal.NotifyContext` у `main.go` |

Дві речі в образі не декоративні, і обидві перевірені наживо:

- **CA bundle** (`ca-certificates.crt`). Без нього кожен виклик
  `api.telegram.org` падає з `x509: certificate signed by unknown authority`.
  Доказ, що копія працює: запуск із підробленим токеном дістає від Telegram
  **HTTP 401 `Unauthorized`** — це відповідь сервера, тобто TLS-рукостискання
  відбулося.
- **`/usr/share/zoneinfo`**. Інструмент агента `current_time` викликає
  `time.LoadLocation("Europe/Kyiv")`, а в `scratch` цієї теки немає. Без копії
  виклик **щоразу** падає з `unknown time zone Europe/Kyiv` — перевірено на
  мінімальному образі. Альтернатива — `_ "time/tzdata"` в `main.go`: вона
  вшиває базу в бінарник (+384 КіБ бінарника, +98 КіБ образу проти +184 КіБ
  тут). Обрано копіювання, щоб Go-код не знав про контейнер.

### Чому `apps/.env` не потрапляє в образ

Поруч із Dockerfile лежить `Dockerfile.dockerignore`. Docker підхоплює його
автоматично, бо той названий `<Dockerfile>.dockerignore`; кореневий
`.dockerignore` тут не діє — правило вмикається лише явним `-f`. Контекст
звужується до `go.mod`, `go.sum`, трьох `internal`-пакетів і
`demo/6_adk_telegram_bot`; `apps/.env` у нього не входить, і окреме правило
`**/.env` закриває його повторно — щоб майбутнє `!apps/` не відкрило його знову.

```bash
task demo:6_tg:image:verify
# ok: binary + zoneinfo present, apps/.env absent
```

> **Пастка в синтаксисі.** Заперечений **каталог** повертає в контекст усе
> своє піддерево: провідний `**` матчиться на кожній глибині, а власний запис
> батька керує дітьми. Тому `!demo/` відкриває не одну теку, а **кожне** демо —
> саме так перша версія цього файлу лишила `demo/1_ai-gateway` у контексті.
> Називайте точну теку, як у файлі.

## Межі демо

- Тільки текст. Голосові повідомлення, кнопки підтвердження й теми форуму є в
  повнорозмірному `telegram-acp-shim`, з якого цей приклад узятий за зразок;
  тут їх немає навмисно.
- Один агент без інструментів предметної області. Додайте свої через
  `functiontool.New` в `newAgent` — це та сама вісь, що в лабах тижня 2.
- Немає webhook: довге опитування працює без публічної адреси, тож бот
  запускається з ноутбука.
- В образі немає `apps/.env`, і це навмисно: `adkenv.Load` спокійно переживає
  відсутній файл і бере конфігурацію з оточення процесу. Файл `README.md` у
  теці теж не копіюється — він не потрібен, щоб зібрати бінарник.
