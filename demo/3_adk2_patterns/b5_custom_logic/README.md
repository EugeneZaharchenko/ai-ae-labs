# B5 · Custom Logic

**Хто вирішує наступний крок:** код · **Категорія:** B · детермінована оркестрація

Оркестрація — звичайним Go-кодом (цикли, умови, обробка помилок) усередині
динамічного вузла. Водночас кожен дочірній запуск лишається довговічним і
видимим: успішні активації дітей кешуються і пропускаються під час відновлення.

```
Start → checkout (DynamicNode) ──RunNode──→ price_line ×N (по одному на рядок)
                               → notify (LlmAgent)
```

## Запуск

```bash
go run .                                        # сценарне демо, без ключа
go run . -input "ORD-7: 1x gizmo, 0x widget"    # жодного валідного рядка — замовлення падає
go run . -live                                  # notify на моделі з apps/.env
go run . console                                # діалог у консолі
go run . web api webui                          # Web UI на http://localhost:8080/ui/
```

Очікуваний слід офлайн-демо:

```
⚙️  price_line ⇒ {"sku":"widget","cents":900}
⚙️  price_line ⇒ {"sku":"gadget","cents":1299}
⚙️  price_line ⇒ {"sku":"widget","cents":450}
⚙️  checkout ⇒ {"order":"ORD-9","total_cents":2649,"lines_ok":3,"skipped":["line 3: unknown sku \"unobtainium\""]}
🤖 notify: Order confirmed. Details: {…}
```

## Go-примітиви (ADK Go v2.4.0)

| Примітив | Роль у демо |
|---|---|
| `workflow.NewDynamicNode[IN,OUT](name, fn, cfg)` | `checkout`; тіло має тип `workflow.DynamicFn[IN,OUT]` |
| `workflow.RunNode[OUT](ctx, child, input, opts…)` | запуск `price_line` для кожного рядка |
| `workflow.WithRunID(id)` | стабільна ідентичність дитини (`price_line@line-2`) — ідемпотентне відтворення |
| `workflow.ErrNodeFailed` | обгортка помилки дитини, яку бачить батько |

Типу з назвою `DynamicNode` у Go немає: конструктор повертає `workflow.Node`.

## Коли брати

Реальний бізнес-процес розгалужується так, що статичний DAG стає потворним.
Динамічний вузол дозволяє написати цикл звичайним кодом і не втратити durable
execution.

## Коли не брати

Коли статичний граф виражає це ясно. Беріть B5 тоді, коли граф уже заважає, а
не раніше: ви втрачаєте властивість «подивився на граф — побачив потік».

## Що подивитися в коді

- Обробка помилок — звичайний Go: невалідний рядок пропускається, замовлення
  йде далі; якщо не лишилось жодного рядка — вузол повертає помилку.
- Кожен пропущений рядок каже **чому** (`reason`). Нюанс v2.4.0: `RunNode` не
  зберігає ланцюг помилки дитини — `errors.Is(err, errUnknownSKU)` дає `false`,
  зберігається лише `workflow.ErrNodeFailed`, а текст помилки дитини вклеєно в
  повідомлення.
- `RerunOnResume` для динамічних вузлів за замовчуванням `true`: після
  відновлення тіло виконується знову, тож побічні ефекти мають бути в дітях із
  `WithRunID` (їхній результат береться з кешу), а не в самому тілі.
- `RunNode` можна викликати лише з тіла динамічного вузла; поза ним —
  `workflow.ErrInvalidRunNodeContext`.
