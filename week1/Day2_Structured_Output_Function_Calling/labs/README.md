## Ранній win — 3 хвилини, **без API-ключа й без мережі**


**Очікуваний вивід:** у stderr — рядок `rates: offline fixture (USD/EUR/PLN)`,
далі консольний launcher. Спитайте: `Скільки буде 100 доларів у гривнях?`

Це навмисно перший крок дня: **ви маєте побачити типізований виклик
інструмента раніше, ніж витратите час на ключі**. Прапорець `-offline` бере

Далі — з живими курсами й реальною моделлю:

```bash
export GOOGLE_API_KEY=...
go run ./week1/Day2_Structured_Output_Function_Calling/labs console
```

Обидва джерела курсів — без ключа й без реєстрації, обираються прапорцем
`-provider`:

```bash
go run . console                      # НБУ (дефолт): офіційні курси bank.gov.ua
go run . -provider monobank console   # monobank: купівля/продаж api.monobank.ua
```

| | НБУ (`nbu`, дефолт) | Monobank (`-provider monobank`) |
|---|---|---|
| Ендпоінт | `bank.gov.ua/NBUStatService/...` | `api.monobank.ua/bank/currency` |
| Що це за курс | офіційний довідник НБУ | купівля/продаж банку (беремо середнє) |
| Ключ | не потрібен | не потрібен |
| Публічний ліміт | — | не частіше ніж раз на 5 хв (закешуйте, не ретраїть) |
| Кеш у лабі | 1 хв TTL + 1 хв limiter | той самий, спільний клієнт |
| `RateOutput.Source` | `nbu` | `monobank` |

Прапорець змінює **тільки** джерело курсів: контракт інструмента
(`RateInput`/`RateOutput`), валідація й agent однакові. Саме тому обидва
живуть за одним інтерфейсом `Provider` — змінюється реалізація, не контракт.

### Кеш і лімітер HTTP-викликів (`week1/internal/ratecache`)

Обидва провайдери дефолтно ходять у мережу через `ratecache.CachedTransport`:
**TTL 1 хвилина** + **не частіше ніж 1 запит на хвилину на
URL**. Це два різні регулятори, і обидва потрібні:

- **TTL** — «наскільки старою може бути відповідь із кешу». Три питання
  агента за хвилину — це **один** upstream-запит, не три.
- **MinInterval** — «як скоро можна знову вдарити в API після cache miss».
  Монобанк публікує контракт «раз на 5 хвилин» на `/bank/currency`; лімітер
  якраз і не дає кожному витіканню TTL перетворитись на негайний ретрай.
  Якщо кеш прострочений, але ліміт ще не минув — чесно віддається stale
  копія, а не нуль.

Додаткові гарантії (усі закриті тестами): паралельні виклики того самого URL
чекають на один спільний fetch (singleflight), а не змагаються; кешуються
лише `GET`; помилки (5xx/timeout) у кеш не потрапляють; тіло відповіді
буферизується, тож і виклик, і кеш читають кожен свою копію. Кеш живе
в межах процесу — перезапуск лаби робить свіжий запит. Тестування
вимкнення/налаштування: передайте свій `HTTPClient` без `CachedTransport`.

### Зовнішня tool межа наживо: `mono-go-mcp`

Лекція каже «MCP — пізніше»; у цій лабі він уже тут. Провайдер
[`github.com/dimetron/mono-go-mcp`](https://github.com/dimetron/mono-go-mcp)
(офіційний Go SDK MCP) виставляє monobank API як **5 MCP-інструментів**;
агент підключається до нього через ADK `mcptoolset` — той самий шлях, що
слайд «MCP — усередині. A2A — між» описує словами.

```bash
go install github.com/dimetron/mono-go-mcp/cmd/mono-go-mcp@latest
go run . console        # агент із ДВОМА tool-джерелами: локальний + MCP
go run . -no-mcp console  # лише локальний tool (те саме ДЗ без MCP)
```

Перший рядок у stderr скаже `mcp: mono-go-mcp toolset attached (4 tools: ...)`,
і модель побачить і `get_exchange_rate`, і `mono_currency_rates` (плюс 2
`/personal/*` tool-и, яким потрібен `MONO_TOKEN`). Це і є живий
«зовнішня tool boundary»: той самий курс валют — інший процес, інший
протокол, та сама відповідальність валідувати. Кеш upstream (5 хв у
mono-go-mcp) + кеш клієнта (1 хв у лабі) = реальні виклики API
обмежуються лімітами обох шарів.

`mono_set_webhook` сервер виставляє, але агент його **навмисно не пропонує**
(`mcptool.Withheld` у `week1/internal/mcptool`): це POST на `/personal/webhook`, який
змінює стан акаунта, а лаба його ніколи не потребує. Другий рядок у stderr
називає цей список явно — least agency: модель не може зловжити tool-ом,
якого їй не дали.

**Чому MCP-інструменти розв'язуються заздалегідь.** ADK Web UI малює граф
агента з `Reveal(agent).Tools` — і **лише** звідти; `.Toolsets` генератор не
читає взагалі, а назви MCP-інструментів не існують, доки не виконано живий
`tools/list`. Тому лаба розкриває toolset у статичний список на старті
(`ResolveToolsets`), і граф показує всі 6 вузлів замість двох. Ціна названа
прямо: `tools/list` тепер один раз на старті, тож tool, доданий у працюючий
MCP-сервер, з'явиться лише після перезапуску процесу.

| MCP tool | monobank ендпоінт | auth | агент пропонує |
|---|---|---|---|
| `mono_currency_rates` | GET /bank/currency | публічний | так |
| `mono_bank_sync` | GET /bank/sync | публічний | так |
| `mono_client_info` | GET /personal/client-info | `MONO_TOKEN`, 1 запит/60 с | так |
| `mono_statement` | GET /personal/statement/... | `MONO_TOKEN`, 1 запит/60 с | так |
| `mono_set_webhook` | POST /personal/webhook | `MONO_TOKEN` | **ні** |

Бінарника немає — агент чесно скаже `mcp: mono-go-mcp not found
(continuing with the local tool only)` й запуститься з одним локальним
tool-ом (least agency). Прапорець `-no-mcp` прибирає спробу саме тоді,
коли вона не потрібна.

## Що саме тут відбувається

Сьогоднішня межа однією фразою: **модель не виконує інструмент — вона просить
його викликати, а виконує довірений код**. У цій лабі цей поділ видно фізично:

| Шар | Файл | Хто йому довіряє |
|---|---|---|
| Опис інструмента (`name`, `description`, схема параметрів) | `agent.go` — `functiontool.New` | Модель читає це й вирішує, чи кликати. |
| Типізований вхід/вихід | `rates.go` — `RateInput` / `RateOutput` | Компілятор. Схема виводиться з Go-структур — **один source of truth**. |
| Валідація на межі | `rates.go` — `normalizeCode`, `Convert` | Ваш код. Тут і тільки тут вирішується, чи запит взагалі законний. |
| Виконання дії | `rates.go` — `NBUProvider.RatesToUAH` | Ваш код. Модель сюди не дістає. |

**Що тут читати, а що ні.** Мета цієї лаби — контракт інструмента, тож редагувати
треба рівно два файли: `rates.go` (типи, валідація, провайдери) і `main.go`
(wiring). Решта — інфраструктура, яку винесено з вашого поля зору в окремі
пакети, щоб чотири файли не губилися серед семи:

| Пакет | Що робить | Чому не в `labs/` |
|---|---|---|
| `week1/internal/ratecache` | кеш + лімітер HTTP (`CachedTransport`) | ви це не пишете й не правите — це stdlib-RoundTripper, спільний для обох провайдерів. |
| `week1/internal/mcptool` | зовнішня MCP-межа (`mono-go-mcp`) | чужий протокол і чужий сервер: ваш tool локальний, і саме тому MCP винесено за видиму межу. |
| `internal/modelcfg` | вибір провайдера й моделі (`Load`, `LoadEnv`) | те саме рішення потрібне лабам 3 і 4; тримаємо один відповідь на одне питання. |

`agent.go` і `compare.go` лишаються в `labs/` навмисно: перший — це і є контракт
інструмента (`NewRateTool`), до якого прив'язаний `rates.go`, а другий показує,
що той самий контракт обслуговує й іншого споживача, ніж агент.

Ключове — два різні рівні відмови, і обидва спрацьовують **вже після** того, як
JSON від моделі виявився бездоганно валідним:

- `normalizeCode` — форма (`ErrInvalidCode`): три літери, ISO 4217.
- `rateToUAH` — реальність (`ErrUnknownCurrency`): такий код існує, але його
  немає в довіднику джерела — НБУ та monobank котирують різні набори валют
  (`rateToUAH` не знає, який саме провайдер відповів, і не мусить).

Друга перевірка і є `shape ≠ intent` у чистому вигляді: схема гарантувала
*форму*, а не *намір*, не *існування* й не *дозвіл*. Жодна JSON Schema не
знає, які валюти сьогодні котирують НБУ чи monobank — це знає ваш код, і саме
тому валідація живе на межі, а не в описі інструмента.

### Вибір провайдера

Логіка **та сама, що в Дні 1**, і тепер це **той самий код**: `internal/modelcfg`
(`modelcfg.Load`) — щоб два дні не могли розійтися в тому, яка модель відповідає.
Порядок розв'язання:

1. `DEFAULT_MODEL_PROVIDER` називає провайдера; модель — з `MODEL`, інакше з
   `<PROVIDER>_MODEL`, інакше дефолт цього провайдера.
2. Сам лише `MODEL` називає модель **цілком**: префікс маршруту визначає
   провайдера, а якщо префікса немає — відповідає `pimodels`.
3. Нічого не задано — провайдер за наявним ключем, у порядку таблиці:
   agentgateway → ollama → gemini → openai.

Кожна відмова гучна й називає відомих провайдерів; мовчазного фолбека немає.

| Змінна | Провайдер | Навіщо |
|---|---|---|
| `AGENTGATEWAY_BASE_URL` | `agentgateway/*` | Найвищий пріоритет: коли гейтвей піднято, **весь** трафік має йти крізь нього, інакше в трасах і в обліку вартості будуть дірки. |
| `OLLAMA_BASE_URL` | `ollama` | Self-hosted. |
| `GOOGLE_API_KEY` / `GEMINI_API_KEY` | `gemini` | Дефолт курсу. |
| `OPENAI_API_KEY` | `openai` | — |

> ⚠️ **`ANTHROPIC_API_KEY` сам по собі не запустить лабу** — бо рядка Anthropic
> немає в таблиці провайдерів, і лаба лишається на шляхах ADK Go v2.5.0 (його
> модельні пакети — `gemini`, `openaimodel`, `apigee`; бекенда Anthropic немає).
> Це та сама межа, що в Дні 1, тож обидва дні поводяться однаково.
>
> Чому це варто проговорити вголос: `pi-go`/`pimodels` Anthropic **уміє**. Тож
> «Anthropic не працює» — це рішення *цієї* лаби (триматися ADK), а не
> неможливість узагалі. Хочете його — маршрут `agentgateway/anthropic/...` або
> `DEFAULT_MODEL_PROVIDER` з відповідним рядком у таблиці.

## Core path — що має бути в здачі

1. Доменна структура як Go-struct із тегами.
2. JSON Schema, **виведена** зі структури, а не написана руками другий раз.
3. Виклик моделі зі structured output.
4. Десеріалізація у структуру + валідація на межі.
5. **Fail path**: невалідний вихід або ремонтується, або чесно падає.
   Регулярка по тексту — не відповідь.
6. У README — коротке пояснення «Prompt vs Contract» своїми словами.

> **Правило «своїми словами» — не формальність.** У RCT PNAS (Bastani et al.,
> 2025, ~1 000 студентів) група з AI-помічником була на +48 % кращою на
> практиці й на −17 % гіршою на іспиті без нього. Це не «не користуйтесь
> інструментом» — це «швидше зробиш ≠ швидше навчишся». Пункт 6 не оцінюється
> строго й не виноситься в тест; він тут заради вас.

   (`https://mcp.silpo.ua/mcp`, [док](https://ai-factory.silpo.ua/docs/mcp):
   `tools/list` → 39 tool-ів з реальними схемами, OAuth 2.1 + PKCE) або
   **сервер** навколо власного `get_exchange_rate` (`mcp.AddTool` +
   `mcp.NewStreamableHTTPHandler`). Деталі й мета — в ДЗ, розділ
   «🔥 Бонус-трек: MCP».
1. **Fault injection.** Змусьте провайдера повертати три класи збоїв із
   таксономії *AgentChaos* (arXiv:2608.06790) — omission, value, schema — і
   покажіть, що кожен веде до **явного** результату: ремонт або чесна помилка,
   ніколи до тихої правдоподібної відповіді.
2. **Вузол графа.** Загорніть валідацію у
   `workflow.NewFunctionNode[RateInput, RateOutput]` і налаштуйте retry явно
   через `NodeConfig.RetryConfig`. Це прямий місток у Тиждень 2.
3. **Ціна поверхні інструментів.** Додайте до агента 20 фіктивних інструментів
   і виміряйте, як змінюється точність вибору потрібного. Контрольований
   вимір (arXiv:2608.14036) дає деградацію 29,6 % → 3,3 % при рості пулу
   5 → 100 — перевірте порядок величини на своєму випадку.
4. **Бюджет виходу.** Обмежте розмір відповіді інструмента й покажіть у
   README, скільки токенів це економить на 10 кроках агентного циклу.
