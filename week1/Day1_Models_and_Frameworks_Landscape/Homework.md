# Практичне завдання 1 — «Мій перший агент за 30 хвилин»

> **Станом на 08/2026 (перед використанням потрібно перевірити):** форма CLI gitleaks (`gitleaks git --staged`; `protect`/`detect` застарілі з v8.19 — звірити з `gitleaks --help` поточної версії), доступність betterleaks як альтернативи, рядки моделей для міні-бенчмарку (alias, ціна, GA-статус — за [датованим вікі-знімком](https://www.anthropic.com/news/claude-opus-4-8)).

## Легенда

Сьогодні ви наймаєте собі цифрового стажера. Поки він уміє лише одне: прочитати вашу інструкцію, викликати пошук і відповісти в заданому форматі. Але саме з цього зернятка за шість тижнів виросте ваш **Personal Research Agent**, який наповнюватиме наскрізний артефакт курсу — AI Wiki. Перший крок: зрозуміти, де в цьому стажері LLM, де prompt, де context window, де tool, а де вже починається агентна система.

> **Почніть без прихованих пререквізитів.** Візьміть готовий стартовий шаблон, змініть позначені `TODO` і запустіть його. Можна користуватися coding assistant для пояснення Go-коду, але в README своїми словами поясніть карту термінів і результати замірів. Другий провайдер не потрібен, щоб набрати повний бал за базовий шлях: якщо доступний лише один, повторіть вимір на двох конфігураціях цієї моделі (наприклад, різний reasoning effort) і чесно вкажіть обмеження.

## Ранній win: перший видимий результат за ≤15 хвилин

Перш ніж будь-який налаштування — побачте агента живим. Клонуйте стартовий шаблон, експортуйте `GOOGLE_API_KEY` і виконайте:

```bash

# Варіант 1 Терминал

# Вариант 2 веб

```

Агент відповість у консолі. Все — ваш перший ADK-агент запущений, ще до безпеки й бенчмарку. Далі ми зробимо з нього інженерний артефакт.

## Крок 0 — Setup (обов'язково, ~15 хвилин, робимо до основного завдання)

Цього тижня ви вперше отримуєте **справжні ключі провайдерів**. Ключ, залитий у публічний репозиторій, — це одночасно компрометація і рахунок: боти сканують свіжі коміти на GitHub швидше, ніж ви встигаєте зробити `git push --force`. Тому перш ніж писати код агента, ставимо дві речі.

### 0.1. Асистент для коду

Поставте **один** інструмент і перевірте, що він запускається:

- **Claude Code** — `npm i -g @anthropic-ai/claude-code`, далі `claude` у теці проєкту;
- або **OpenAI Codex CLI** — `npm i -g @openai/codex`, далі `codex`;
- або просто веб-версія ChatGPT / Claude у браузері, якщо CLI не ставиться.

Асистентом **можна** користуватися для пояснення Go-коду та розбору помилок компілятора — це не списування, а нормальний робочий інструмент 2026 року. Але карту термінів і висновки в README ви пишете **своїми словами**: саме їх читає й оцінює ментор.

> **Чому правило «своїми словами» — не формальність.** Є контрольоване дослідження (Bastani et al., *PNAS* 2025, RCT на ~1 000 студентів): неогороджений AI-асистент дає **+48 % на практиці** і **−17 % на іспиті, коли інструмент забрали** — гірше, ніж зовсім без нього; а варіант із підказками замість відповідей прибирає штраф, але приросту теж не дає. Точність відповідей не була причиною — причиною була залежність. Інженери називають той самий ефект на рівні команди «борг розуміння»: код змінюється швидше, ніж люди встигають розуміти, що він робить. Тому в цьому курсі агент **робить** за вас швидше, але README — це те місце, де ви **розумієте**; ми не обіцяємо, що з агентом ви швидше навчитесь, лише що швидше зробите. Опора: [comprehension-debt-human-bottleneck](https://x.com/andrewyng/status/2082199333920027009) (станом на 08/2026).

- *(необов'язково, не оцінюється)* Підключіть до асистента **OpenRouter MCP** — `claude mcp add --transport http openrouter https://mcp.openrouter.ai/mcp` → `claude mcp login openrouter` — і спитайте його, хто зараз у топі за обсягом токенів та хто віддає вашу модель і почому (`list-daily-model-rankings`, `list-model-endpoints`). Це лише спосіб швидше заповнити таблицю бенчмарку, не заміна їй: рейтинг за обсягом — популярність, не якість. Станом на 08/2026; `list-*` інструменти безкоштовні, ключ — окремий, з лімітом $10 і строком 7 днів.

### 0.2. Захист від витоку ключів

Мінімальний шлях — три кроки, кожен перевіряється очима:

1. **`.env` ніколи не потрапляє в git.** Створіть `.gitignore` у корені свого репозиторію:

   ```gitignore
   .env
   .env.*
   !.env.example
   ```

   Ключі тримайте в `.env`, а в репозиторії лишайте `.env.example` з порожніми значеннями (`GOOGLE_API_KEY=`), щоб було видно, які змінні потрібні.

2. **Pre-commit хук, який блокує коміт із секретом.** Ставимо [gitleaks](https://github.com/gitleaks/gitleaks) *(станом на 08/2026 — де-факто стандарт; старі посилання на `zricethezav/gitleaks` тепер редіректять на орг `gitleaks`)*.

   ⚠ **Команди звіряйте з `gitleaks --help` своєї версії.** CLI перебудували: `protect` і `detect` **застаріли й приховані** починаючи з v8.19, а поточна форма для staged-змін — `gitleaks git --staged`. Саме тому в деку цих команд немає: слайд не перевидаси, а CLI змінюється.

   ```bash
   brew install gitleaks          # macOS; Linux — див. releases на GitHub
   mkdir -p .githooks
   cat > .githooks/pre-commit <<'EOF'
   #!/bin/sh
   gitleaks git --staged --redact --verbose || {
     echo "❌ Коміт заблоковано: у staged-змінах знайдено секрет."
     exit 1
   }
   EOF
   chmod +x .githooks/pre-commit
   git config core.hooksPath .githooks
   ```

   > Хук ставимо через `core.hooksPath`, а **не** копіюванням у `.git/hooks/`: так сам файл хука версіонується разом із репозиторієм.
   >
   > **Але не обманюйтесь:** `git config core.hooksPath` пише в `.git/config`, який у git **не** зберігається. Тобто файл приїде з клоном, а увімкнення — ні: кожен, хто клонує репозиторій (і ви самі на новій машині), має виконати цю команду ще раз. Тому крок 3 нижче — не формальність: він доводить, що захист увімкнений **саме тут**.

3. **Перевірка, що це справді працює.** Створіть файл із фейковим ключем (наприклад, рядок виду `GOOGLE_API_KEY=AIzaSy` + 30 випадкових символів), спробуйте його закомітити — і побачте, як хук зупиняє коміт. Скріншот або текст помилки покладіть у README. **Якщо коміт пройшов — хук не працює**, шукайте причину до того, як підключите справжній ключ.

> **Альтернатива:** [betterleaks](https://github.com/betterleaks/betterleaks) розв'язує ту саму задачу *(перевірено 08/2026)*. Для core-шляху беремо **один** сканер — два в обов'язковому setup це зайвий біль і прихований пререквізит. Назви прапорців CLI звіряйте з `gitleaks --help` своєї версії: вони змінюються між релізами.

### 0.3. Локальний моніторинг (необов'язково, але рекомендовано)

Якщо у вас є Docker — підніміть локальний **agentgateway** і пропустіть усі виклики агента через нього. Отримаєте трасу кожного запиту, метрики й **реалізовану вартість у USD** — тобто зможете перевірити, чи правильно ваш бенчмарк рахує гроші.

Окремий бонус для тих, у кого **ще немає жодного API-ключа**: у стеку є mock-бекенд, тож усю лабу можна пройти офлайн і безкоштовно.

Інструкція: [гайд Local Monitoring Agentgateway](https://github.com/dimetron/ai-ae-labs/blob/main/week1/Day1_Models_and_Frameworks_Landscape/guides/Local_Monitoring_Agentgateway.md).

> Це **необов'язкова** частина ДЗ — базові 80 балів зараховуються без цього кроку, Docker був би прихованим пререквізитом. Але порівняння «що виміряв агент» vs «що побачив гейтвей» — це пункт «Два виміри однієї вартості» в `++ Advanced`, тобто воно оцінюється (**+20 додаткових балів** понад базові 80) і при цьому не потрібне для сертифіката.

## Основне завдання

**Ваше завдання —** зібрати свого першого агента на ADK Go v2 зі стартового шаблону [courses/AI_Agents_Engineering/lectures/week1/Day1_Models_and_Frameworks_Landscape/labs/main.go](https://github.com/dimetron/ai-ae-labs/blob/main/week1/Day1_Models_and_Frameworks_Landscape/labs/main.go) і провести міні-`Cross-Model Benchmark Harness (Go)`:

1. Оживіть агента-«планувальника вихідних» у вашому місті: `llmagent.New(llmagent.Config{…})` + вбудований інструмент `geminitool.GoogleSearch{}`; напишіть власну інструкцію (місто, формат відповіді, що агент має відмовлятися робити). Це точна форма з vendored quickstart, тому не треба вгадувати API.
2. Запустіть його через `go run . console` і задокументуйте у README 3 діалоги: план на суботу, «а якщо дощ?», запит поза доменом (агент має відмовити).
3. Додайте короткий context-stress сценарій: дайте агенту 5–10 рядків фейкового внутрішнього довідника під ваш домен прямо в запиті, а потім поставте питання, на яке в цьому контексті немає відповіді. У README поясніть, де контекст допоміг, а де потрібен RAG/пошук замість вигадки.
4. Міні-бенчмарк: запустіть того самого агента на 2–3 конфігураціях моделей (або на двох effort-конфігураціях однієї моделі, якщо у вас один ключ) і порівняйте в таблиці: латентність відповіді, якість плану, приблизна вартість за прайсом. Для кожного рядка вкажіть «станом на серпень 2026» або точну дату свого запуску.
5. Додайте у README дві короткі таблиці: (а) «LLM / prompt / context window / tool / agent / RAG / MCP — що це в моїй лабі»; (б) висновок на 3–5 речень, яку модель ви лишили б цьому агенту й чому.

> Для рядків моделей орієнтуйтеся на [датований вікі-знімок](https://www.anthropic.com/news/claude-opus-4-8), але фіксуйте дату **власного** запуску: alias, ціна й доступність змінюються швидше за домашні дедлайни.

## Альтернативні теми (на вибір)

Та сама механіка (один `LlmAgent` + пошук + порівняння моделей), інший домен:

- **Security:** агент-дайджест новин безпеки — щоранку збирає свіжі CVE та інциденти для вашого стеку (Go, Kubernetes, Postgres…) і відмовляється обговорювати щось інше.
- **Research:** агент-оглядач наукових новин за однією темою (наприклад, agentic AI) — 5 найсвіжіших публікацій із посиланнями.
- **Fun:** гід вуличної їжі та подій — «куди піти поїсти й що подивитися сьогодні ввечері» у вашому місті.

## ++ Advanced (до 20 балів, для сеньйорів)

- Конкурентний бенчмарк: goroutines + `errgroup`, однакові промпти на всі моделі одночасно, retry/backoff з експоненційною затримкою на rate limits + один тест на нього.
- Порівняйте той самий quickstart на ADK Python — 3–5 речень у README: що дає Go-версія (типізація, один бінарник), що зручніше в Python.
- **Сканування всієї історії, а не тільки staged-змін.** Pre-commit хук ловить лише те, що ви комітите *зараз*. Додайте CI-крок (GitHub Actions), який ганяє `gitleaks git --log-opts="--all"` по **всій** історії репозиторію (стара форма `gitleaks detect` застаріла з v8.19 — станом на 08/2026 актуальна команда для git-історії — `gitleaks git`), і поясніть у README, чому одного хука недостатньо (його можна обійти через `--no-verify`, і він нічого не знає про коміти, зроблені до його встановлення).
- **Два виміри однієї вартості.** Пропустіть бенчмарк через локальний agentgateway (див. [гайд Local Monitoring Agentgateway](https://github.com/dimetron/ai-ae-labs/blob/main/week1/Day1_Models_and_Frameworks_Landscape/guides/Local_Monitoring_Agentgateway.md)) і порівняйте в README вартість, яку порахував ваш харнес, із `cost_total` з access-log гейтвея. Поясніть розбіжність: вартість вимірюють на межі системи, а не всередині агента.
- **Процедура ротації злитого ключа.** Опишіть у README 5–7 рядками, що робити, якщо ключ уже потрапив у публічну історію. Головна теза, яку треба сформулювати явно: **сканер не «прибирає» секрет**. Переписування історії (`git filter-repo`) не відкликає ключ — він уже в чиємусь дампі. Єдиний реальний перший крок — **відкликати й перевипустити ключ у консолі провайдера**, і тільки потім чистити історію.

## 🔥 Бонус-трек (не оцінюється, не потрібен для сертифіката)

- Запустіть benchmark harness на **трьох** конфігураціях однієї моделі (наприклад, три значення reasoning effort) і порівняйте форму кривих «латентність × якість × вартість» — чи повторюється розрив між моделями всередині однієї моделі. Балів не дає; робиться для себе.

## Якщо щось не працює

| Симптом | Що перевірити |
|---|---|
| `go run . console` падає або агент не відповідає | Спершу `GOOGLE_API_KEY` у `.env` (чи експортований у середовище), а не код агента. Порожній або неправильний ключ — найчастіша причина. |
| `go: command not found` або помилки збірки на свіжому Go | `go version` має показувати ≥ 1.25. У Codespaces стартового шаблону версія вже правильна — локально оновіть Go. |
| Коміт із фейковим ключем **пройшов** (Крок 0.2.3) | Хук не активований: виконайте `git config core.hooksPath .githooks` ще раз **у цьому клоні** — налаштування не переїжджає з клоном. Перевірте також `chmod +x` на файлі хука. |
| Помилка 429 / rate limit під час бенчмарку | Це не поломка: сервер сам каже, скільки чекати (`try again in …s`). Зачекайте й повторіть; розбір полів відповіді — у FAQ #17. |
| Модель з таблиці «не існує» (404 / invalid model) | Alias застарів: звірте актуальну назву на [models.dev](https://models.dev/) і зафіксуйте дату свого запуску в README. |

Якщо жоден рядок не допоміг — опишіть симптом на форумі вебінару: точна команда + повний текст помилки.

## Критерії оцінювання

| Критерій | Бали |
|---|---|
| Агент компілюється (`go build ./...`) і працює через console launcher | 20 |
| Власна доменна інструкція + продемонстрована відмова поза доменом | 15 |
| Три діалоги + context-stress сценарій із чесним поясненням, де потрібен RAG/пошук | 15 |
| Порівняння 2–3 моделей у таблиці (латентність/якість/вартість) | 20 |
| README: як запустити, які моделі, позначка «станом на [місяць/рік]», фундаментальна карта термінів, висновок + доказ робочого anti-leak хука з Кроку 0 | 10 |
| ++ Advanced (бонус) | 20 |
| **Разом** | **100** |

Базове завдання дає до 80 балів; ++ Advanced — це **+20 додаткових балів** (разом 100). 🔥 Бонус-трек не оцінюється взагалі. Альтернативна тема оцінюється за тими самими критеріями.
