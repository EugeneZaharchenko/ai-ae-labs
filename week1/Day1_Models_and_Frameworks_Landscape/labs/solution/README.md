## Як запустити

```bash
cd week1/Day1_Models_and_Frameworks_Landscape/labs/solution

go run .            # БЕЗ ключа й без мережі
go run . -live      # реальні провайдери
go run . -live -n 5 # 5 прогонів на модель

go test . -race
go vet  .
```

Офлайн-режим підставляє скриптовану модель замість провайдера. Латентність у ньому
не означає нічого — запиту в мережу немає. А от **токени, токенайзери й арифметика
вартості цілком справжні**: на однаковому тексті три моделі дають 157 / 179 / 209
вхідних токенів, і саме це пояснює, чому нижча ціна за токен не дорівнює нижчому
рахунку за задачу.

`-live` пропускає неналаштованих провайдерів **вголос** (рядок у stderr) і рахує
тих, хто лишився. Мовчазний пропуск дав би таблицю на дві моделі, яку прочитали б
як таблицю на три.

## Що з STEARING демонструє цей код

**«Lab artifact — Ensure the lab produces a measurable `Cross-Model Benchmark Harness`,
not an opinionated model ranking.»**
`Compare` сортує рядки за **назвою моделі**, а не за вартістю чи латентністю: сортування
за метрикою — це вже рейтинг, а рейтинг ховає компроміс (найдешевша може не проходити
за data residency). Закріплено тестом `TestReportIsMeasurementNotRanking`.

**«Token economics — effective cost, not just provider price sheets: tokenizer behavior,
input/output tokens, prompt/context growth.»**
`Cost()` рахує вхід і вихід за різними ставками; `Tokenizer.Estimate` рахує **руни**,
а не байти (для української різниця — вдвічі). `TestCheaperPriceSheetCanCostMore` показує
кейс «Sonnet 5»: модель із **нижчим** прайсом за токен виходить **дорожчою** за задачу
через щільніший токенайзер. `requestText` рахує й системну інструкцію — той невидимий
рахунок, який платять у кожному виклику. Кожен прогін іде у власній сесії, інакше
ви виміряєте зростання контексту, а не модель.

**«Context window — bounded working memory.»**
`ModelSpec.FitsContext` відсіює завеликий сценарій **до** виклику: провайдер відхилить
запит уже після того, як порахує вхідні токени. `TestRunScenarioRefusesToPayForAnOverflow`
перевіряє не лише помилку, а й що `CallCount() == 0` — тобто що грошей не витрачено.

**«Reasoning effort — a cost/latency/quality knob.»**
`ReasoningEffort` у каталозі → `genai.ThinkingConfig{ThinkingLevel: …}`, а `ThoughtTokens`
оплачуються як вихідні (`Usage.BilledOutput`). Бюджет «роздумів» стає окремою колонкою
`think tok` у таблиці, а не абзацом у слайді.

**«Model snapshot — a dated snapshot, verified before use.»**
Список моделей **не захардкоджений**. `LoadCatalog` падає, якщо в каталозі немає `as_of`,
якщо є дублікат id, якщо в ключі друкарська помилка (`DisallowUnknownFields`) або якщо
прайс неповний. Дата доїжджає до кожного рядка таблиці — колонка `станом на`.

**«Explain … Practical Example of Go model providers (Ollama, Gemini, Codex OpenAI).»**
`BuildModel` покриває всі три бекенди ADK Go v2.5.0: `gemini`, `openaimodel` і Ollama
через `openaimodel.ClientConfig.BaseURL`. Anthropic-бекенда в ADK Go **немає** —
`TestBuildModelFailsLoudly` фіксує це як читабельну помилку, а не як 401 на першому запиті.

**«Early win (P0)» / «ЦА = Junior–Middle».**
`go run .` без жодного ключа одразу друкує повну таблицю. Нуль пререквізитів, нуль setup.

**«Business risks — cost surprise, vendor lock-in.»**
Колонка `$/задача` — це відповідь на питання «скільки це коштує», а `provider` +
`catalog.json` — на «як швидко ми звідси з'їдемо».

**«Part 2 bridge.»**
Тут агент повертає текст, і harness міряє його довжину. Довжина ≠ коректність:
щоб перевіряти *зміст*, потрібні типізовані контракти — це Частина 2.

## Що варто сказати вголос на камеру

**Один прогін — це не бенчмарк.** Таблиця друкує `n`, медіану **і** розкид `min–max`
саме тому, що середнє з трьох вимірів, один з яких застряг на 5 секундах, — це
художній твір. Медіана стійка до викиду, розкид показує, чого медіана не показує.

**Однаковий конфіг ≠ однакова поведінка.** `ThinkingConfig` — це поле `genai`;
бекенд Gemini його поважає, `openaimodel` (OpenAI, Ollama) може просто проігнорувати.
Тоді колонка `think tok` чесно покаже нулі. Це не баг харнесу — це діалекти API,
і про них треба знати до того, як ви побудуєте на «однаковому конфізі» продакшн-роутинг.

**Метрику знімають колбеками, а не обгорткою навколо моделі.** ADK для цього має
`BeforeModelCallbacks` / `AfterModelCallbacks` («ideal place to … collect metrics on
token usage»). Обгортка теж працює — рівно до першого workflow-графа з кількома
моделями. Обмеження нашого `Meter`: пара «старт → фініш» одна на екземпляр, тож для
паралельних гілок (Тиждень 6) кожна гілка потребує власного `Meter`.
