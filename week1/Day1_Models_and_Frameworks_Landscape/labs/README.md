## Ранній win — 5 хвилин, без теорії

Мета цього кроку одна: побачити, що агент **працює**, ще до того, як ви
зрозумієте, чому він агент. Теорія — після.

```bash
cd courses/AI_Agents_Engineering/lectures
export GOOGLE_API_KEY=...            # ключ Google AI Studio
go run ./week1/Day1_Models_and_Frameworks_Landscape/labs console
```

**Очікуваний вивід:** консольний launcher ADK друкує запрошення й чекає на
запит. Введіть `Що відбувається у моєму місті цими вихідними?` — за кілька
секунд отримаєте відповідь; якщо агент вирішить, що йому потрібен пошук, ви
побачите виклик `google_search` у виводі.

Без інтерактиву — той самий агент через пайп (саме так зручно ганяти бенчмарк):

```bash
echo "Яка погода у Львові?" | MODEL=gemini-3.8-flash go run ./week1/Day1_Models_and_Frameworks_Landscape/labs
```

**Очікуваний вивід:** одна відповідь у stdout і завершення процесу. Без
аргументів launcher бере перший sublauncher (`console`), а `console` читає
`os.Stdin` і сам вимикає streaming, коли stdout не є терміналом.

### Який провайдер запускається

Нічого задавати не обов'язково: стартер визначає провайдера за наявними
credentials. Пріоритет: `agentgateway` → `ollama` → `gemini` → `openai`
(порядок з AGENTS.md §3). Далі перший рядок зводить усе докупи:

| Що задано | Що запускається |
|---|---|
| нічого | провайдер за наявним ключем, модель — його дефолт |
| `DEFAULT_MODEL_PROVIDER=…` | названий провайдер; модель — з `<PROVIDER>_MODEL` або його дефолт |
| `MODEL=…` (повне ім'я з префіксом) | провайдер із префікса, модель — як задано |
| `MODEL=…` (голий id, напр. `gpt-5.6-luna`) | провайдера підказує `pimodels`, модель — як задано |

> `MODEL` — це ім'я моделі **цілком**, разом із префіксом маршруту: один рядок
> `MODEL=agentgateway/openai/gpt-5.6-luna` перемикає і провайдера, і модель.

Провайдера задають через `DEFAULT_MODEL_PROVIDER`. Три `agentgateway`-рядки —
це три **різні** маршрути одного шлюзу, і саме тому вони окремі:

| `DEFAULT_MODEL_PROVIDER` | Дефолтна модель | Куди йде запит |
|---|---|---|
| `agentgateway/ollama` | `qwen3.5:4b-mlx` | локальний демон Ollama через шлюз на `:4000` |
| `agentgateway/openai` | `gpt-5.6-luna` | OpenAI API через шлюз на `:4000` |
| `agentgateway/gemini` | `gemini-3.8-flash` | Gemini API через шлюз на `:4000` |
| `ollama` | `deepseek-v4.1-flash:cloud` | Ollama напряму (`OLLAMA_BASE_URL`) |
| `gemini` | `gemini-3.8-flash` | Gemini API (`GOOGLE_API_KEY` / `GEMINI_API_KEY`) |
| `openai` | `gpt-5.6-luna` | OpenAI API (`OPENAI_API_KEY`) |

Для агента це просто імена моделей. Різницю в поведінці — ціну, ліцензію,
data residency — створює **маршрут**, а не код агента: та сама модель за
шлюзом і напряму має різну спостережуваність і різний рахунок.

Невідомий `DEFAULT_MODEL_PROVIDER` — гучна помилка на старті зі списком
відомих провайдерів, а не мовчазний фолбек: краще впасти одразу, ніж
відбенчмаркати не той бекенд.

> **Якщо ви ніколи не писали на Go — цього достатньо.** Сьогодні ви змінюєте
> готові рядки й запускаєте команду. Вчити Go цілком не потрібно.

## Карта фундаментів: де кожен термін лекції живе в цьому коді

Це — головна таблиця дня. Сім слів «нульового словника» з Блоку 1 лекції,
прив'язані до **вашого власного артефакту**, а не до абстракції. Перенесіть цю
таблицю у свій README і заповніть третю колонку своїми словами (це п. 6 ДЗ).

| Термін | Де саме в цій лабі | Що це означає для вас |
|---|---|---|
| **LLM** | `createModel` у `provider.go` | Модель, яка генерує текст. Змінюється однією змінною `MODEL` — і це навмисно. `pimodels` вирішує, який бекенд стоїть за ім'ям. |
| **Provider / routing** | `providerDefaults` + `chooseModel` у `provider.go` | Не термін зі словника лекції, але шоста вісь рішення тут стає кодом: те саме ім'я моделі напряму й через шлюз — різні ціна, латентність і спостережуваність. |
| **Prompt / Instruction** | поле `Instruction` у `llmagent.Config` | Правила поведінки агента: для кого він, який формат відповіді, коли відмовлятися. Не «чарівні слова» — контроль. |
| **Context window** | усе, що поїхало в один виклик: інструкція + історія + результат пошуку | Обмежений **стіл**, а не бібліотека. Заповніть його — і платите за кожен токен щоразу. |
| **Tool** | `geminitool.GoogleSearch{}` у полі `Tools` | Конкретна дія, яку виконує код **поза** моделлю. Модель тільки просить її викликати. |
| **Agent** | усе разом: `llmagent.New(...)` + `launcher` | Модель + інструкція + інструменти + харнес, який усім цим керує. Саме харнес робить із LLM-виклику агента. |
| **RAG / embeddings** | ❌ у цій лабі немає — і це показово | Відповідь на «знання компанії не влізають у контекст». Ви побачите межу в Завданні 3, а будуватимемо — у Тижні 3. |
| **MCP** | ❌ у цій лабі немає | Стандартна межа для **зовнішніх** інструментів. Тут інструмент вбудований; MCP — Тиждень 2+. |

Два порожні рядки в таблиці — не пропуск, а зміст: сьогодні ви маєте побачити
**де саме** ці два шари почнуться, і чому їх не можна замінити більшим
контекстним вікном.

## Core path — що має бути в здачі

1. `go run . console` запускається без panic.
2. Власна `Instruction`: домен, формат відповіді, **правило відмови**.
3. Три задокументовані діалоги: корисний · з уточненням · поза доменом (відмова).
4. Context-stress: один запит, де контексту вистачило, і один, де агент має
   чесно сказати «потрібен пошук», а не вигадати.
5. Бенчмарк-таблиця на 2–3 моделях.
6. Карта фундаментів (таблиця вище), заповнена своїми словами.

### Формат бенчмарк-таблиці

```text
| model | latency_ms | quality_note | estimated_cost_usd | as_of | license |
```

Колонка `license` — з 27.08.2026 обов'язкова, і заповнюється **не** словом
«open». Значення беруться з поля `license` / `license_name` на сторінці моделі
в Hugging Face. Станом на 08/2026 всередині одного сімейства Qwen 3.8 живуть
**три різні** ліцензії: `27B` — `apache-2.0`, `Flash-Next` —
`qwen-community-1.0`, `2.4T-A95B` — `qwen3.8-max` (пропрієтарна). MiniMax M3 —
`minimax-community`, Kimi K3 — `kimi-k3`.

Головне, що варто помітити: **ваги всіх цих моделей качаються однаково вільно**
(`gated: false`). Тобто «я зміг завантажити ваги» не доводить нічого про те, чи
можна їх використати. Модель, що виграла ваш бенчмарк, може бути юридично
непридатною для проду — дізнатися про це дешевше зараз, ніж на аудиті. Для
закритих API пишіть `proprietary API`, для відкритих — точну назву ліцензії.

> **Це не рейтинг моделей.** Артефакт дня — **вимірювальний інструмент**.
> «Модель X краща» без таблиці, дати й ліцензії — це думка, а не результат.

## Прогін кількох моделей

```bash
echo "Яка погода у Львові?" | MODEL=gemini-3.8-flash go run ./week1/Day1_Models_and_Frameworks_Landscape/labs
echo "Яка погода у Львові?" | MODEL=gpt-5.6-luna    go run ./week1/Day1_Models_and_Frameworks_Landscape/labs
```

**Правило:** між прогонами ви міняєте **тільки** змінну `MODEL`. Якщо ви правите
код — ви порівнюєте дві різні програми, а не дві моделі.

Порівнювати можна й провайдерів, а не лише моделі: `MODEL` приймає повне ім'я
маршруту, тож та сама модель за шлюзом і напряму — це два рядки вашої таблиці:

```bash
echo "Яка погода у Львові?" | MODEL=agentgateway/openai/gpt-5.6-luna go run ./week1/Day1_Models_and_Frameworks_Landscape/labs
echo "Яка погода у Львові?" | MODEL=gpt-5.6-luna                go run ./week1/Day1_Models_and_Frameworks_Landscape/labs
```

Той самий `MODEL` через шлюз і повз нього дає різні латентність і рахунок. Це не
шум вимірювання: за шлюзом є ще один мережевий хоп і власний облік вартості.

> `gemini-3.8-flash` і `gpt-5.6-luna` — дефолти стартера «станом на 08/2026»;
> звіряйте актуальні id у документації провайдера. Модель, якої провайдер уже
> не обслуговує, падає гучно — з його власною помилкою, — а не тихо бенчмаркається
> під чужим ім'ям (див. `spec/idea.md`, «Design implication»).

## Дві теки з кодом у лабі

Уся логіка вибору провайдера живе в **`provider.go`**, а `main.go` лише збирає
застосунок.

| Файл | Що робить | Чому окремо |
|---|---|---|
| `provider.go` | таблиця `providerDefaults`, `chooseModel`, `LoadModel`, `createModel` | Вибір моделі — інженерне рішення з власними правилами (пріоритет credentials, префікси маршрутів, фолбеки). Своя межа — свої тести. |
| `main.go` | `loadEnv`, `main` | Тільки збірка: оточення → бекенд → агент → launcher. |

Порядок обов'язковий: `loadEnv` викликається **до** `LoadModel`. Це bootstrap
оточення застосунку, а не властивість провайдера, тому він і лишився в `main`.
Якщо поміняти місцями — автовизначення провайдера не побачить ключів з `apps/.env`.

Тести розділені так само: `provider_test.go` — офлайн-перевірки вибору
провайдера (без ключа й без мережі), `main_test.go` — один живий прогін, який
пропускається, коли credentials немає.

## Тести

```bash
cd courses/AI_Agents_Engineering/lectures
go test ./week1/...
```

**Очікуваний вивід:** усі пакети `ok`. Тести не потребують ні API-ключа, ні
мережі.

Табличні тести стартера (`main_test.go`) перевіряють три речі, кожна з яких —
окремий спосіб отримати правдоподібну, але хибну таблицю:

- **розвʼязання імені моделі** (`resolveModelName`): якщо `MODEL` ігнорується,
  ваша таблиця порівнює одну й ту саму модель із собою, і ви цього не помітите;
- **пріоритет вибору** (`chooseModel`): якщо провайдер визначається неправильно,
  правильне ім'я моделі їде не на той бекенд і падає — або відповідає — з причин,
  які не мають нічого спільного з моделлю, яку ви нібито перевіряєте;
- **розвʼязання маршрутів** (`providerForModel`, `TestAgentGatewayRoutesResolveThroughPimodels`):
  `agentgateway/gemini/…` не має зматчитися як `agentgateway/ollama`, інакше
  Gemini-запит іде на локальний демон і падає з «model not found» — повідомленням,
  яке відправляє шукати відсутній `ollama pull` замість помилки маршрутизації.

## Якщо щось не працює

| Симптом | Причина | Що робити |
|---|---|---|
| `Failed to create model: … API key not valid` | ключ не підхопився | `echo $GOOGLE_API_KEY` — порожньо? Експортуйте ще раз у **тому самому** терміналі. |
| Команда мовчить і нічого не друкує | `console` чекає на stdin | Це нормально: введіть запит і натисніть Enter. Або подайте пайпом. |
| `go: go.mod requires go >= 1.27` | стара тулчейн | `go version`; оновіть Go до 1.27+. |
| `429 rate limit` | безкоштовна квота вичерпана | Зачекайте інтервал із поля `try again in …` у відповіді сервера. Розбір полів — FAQ #17 лекції. |
| Агент відповідає, але **ніколи** не шукає | інструкція не вимагає пошуку | Додайте в `Instruction` явне «для актуальних подій і погоди ОБОВʼЯЗКОВО використовуй пошук». |
| Агент охоче відповідає на будь-що | немає правила відмови | Додайте межу домену в `Instruction` — це п. 2 core path, а не косметика. |

## 🔥 Бонус-трек (не оцінюється, сертифікат не гейтить)

Цілі, не кроки.

1. **Точна вартість замість оцінки.** Зніміть `usage.input_tokens` /
   `usage.output_tokens` напряму з відповіді провайдера й порахуйте вартість за
   фактом, а не за оцінкою токенів.
2. **Конкурентний прогін із власним backoff.** `errgroup`, retry з **jitter**,
   і `Retry-After` із тіла помилки замість фіксованого інтервалу. Доведіть, що
   два goroutine, які одночасно отримали 429, не синхронізуються й не б'ються
   об ліміт удруге.
3. **Heatmap «модель × тип задачі».** Не «A дешевша за B», а «на короткому QA
   виграє A, на довгому контексті — B». Це вже прообраз роутингу з Курсу 2.
4. **Нульовий бюджет.** Прогоніть харнес через OpenRouter-роутер
   `openrouter/free` (≈23 `:free`-моделі станом на 27.08.2026). Обовʼязково
   назвіть у README, чому з цього шляху **не можна** знімати p50/p95: rate
   limits і латентність нестабільні за визначенням.
