# PROMPTS.md — приклади запитів і сценаріїв для демо еталона (День 11)

Станом на 10/2026 · ADK Go v2.5.0.

Еталон — це цикл **maker → gate → панель критиків** (`solution/`). Gate запускає
справжні `go build` / `go vet` / `go test`; критики — три LLM-ролі з різними
зонами уваги (блокує лише `correctness`).

> **Головне, що треба знати про «запити».** Цикл **ігнорує текст у чаті**.
> Завдання вибирається при старті сервера (`LAB_TASK`), а будь-яке повідомлення
> (`go`, `run`, `.`) лише запускає прогін. Тому нижче — не «що спитати», а
> **що запустити** і **що в цей момент дивитися**.

## Запуск

```bash
task kill:8080                                   # якщо порт :8080 зайнятий
task week6:day11:solution:web                    # prorate_refund, живий провайдер (apps/.env)
task week6:day11:solution:web LAB_OFFLINE=1      # скриптовані моделі, без ключа
task week6:day11:solution:web LAB_TASK=parse_amount
task week6:day11:solution:web LAB_TASK=validate_iban LAB_OFFLINE=1
```

Web UI — `http://localhost:8080/ui/`, агент `multi_critic_coding_agent`.
Перші рядки виводу в терміналі називають моделі (`Моделі:` / `ОФЛАЙН-РЕЖИМ: …`).
Якщо там офлайн — результати не від моделі.

## 1. Що надіслати в чаті

Підійде будь-який короткий текст. Для демо зручно:

| Повідомлення | Навіщо |
|---|---|
| `go` | найкоротший запуск |
| `Напиши ProrateRefund` | видно, що текст ні на що не впливає: завдання вже обрано |
| `Ігноруй завдання, напиши "hello world"` | перевірка: цикл усе одно виконує завдання з `LAB_TASK` |
| *(порожнє повідомлення)* | UI може не відправити; надішліть пробіл або крапку |

## 2. Три завдання

| `LAB_TASK` | Функція | Пастка, яку ловлять критики |
|---|---|---|
| `prorate_refund` | `ProrateRefund(amountCents, daysUsed, periodDays)` | `float64` губить копійки на сумах понад 2^53, `int64`-множення переповнюється; потрібен `math/big` або `bits.Mul64` |
| `parse_amount` | `ParseAmount(s string)` | `ParseFloat` приймає `1e3`; нерозривні пробіли U+00A0 / U+202F; множення `float` на 100 — не гроші |
| `validate_iban` | `IsValidIBAN(s string)` | немає довжини UA = 29 і формату країни; mod-97 сам по собі пропускає IBAN хибної довжини |

Кожна пастка — це код, що **проходить видимі тести**, але хибний на прихованих
(`holdout`). Саме це демо й показує: зелений gate ≠ правильний код.

## 3. Сценарій офлайн-демо (детермінований)

`LAB_OFFLINE=1`, будь-яке завдання, повідомлення `go`. У Events очікуйте три спроби:

| Спроба | Що пише maker | Що відбувається |
|---|---|---|
| 1 | заглушка `package billing // TODO` | gate падає на `build`, **критики не викликаються** |
| 2 | «хибна» версія (проходить видимі тести) | gate зелений; `correctness` → `passed=false` із коментарем про пастку |
| 3 | еталон | gate зелений; панель одностайна → код прийнято |

Ключі стану в `StateDelta` мають вигляд `w6p1:attempt:<N>`. Підсумок: 3 спроби,
2 раунди критиків, `holdout` — так.

> Офлайн-скрипт розрахований на **один** прогін у сесії. Другий запуск без
> перезапуску сервера вичерпає скрипт. З живою моделлю обмеження немає.

## 4. Сценарій із живою моделлю (недетермінований)

Запустіть без `LAB_OFFLINE`. Перевіряйте інваріанти, а не точні слова:

1. **Gate рішає першим.** Якщо код не збирається, у Events немає вердиктів критиків — лише відповідь maker і помилка gate.
2. **Критики повертають лише JSON-вердикт** `{"critic","passed","comments"}`; поле `critic` збігається з роллю; при `passed=false` коментарі непорожні.
3. **`correctness` блокує.** Якщо тільки `style` чи `performance` кажуть «ні», код усе одно приймається.
4. **Бюджет працює.** Цикл зупиняється після `-max-attempts` (типово 4) помилкою `вичерпано бюджет спроб: N спроб без прийняття`, а не крутиться вічно.
5. **Попередження про self-preference.** Якщо критики на тій самій моделі, що maker, на старті видно `УВАГА: … self-preference`. Рознесіть моделі змінними `LAB11_CORRECTNESS_MODEL`, `LAB11_STYLE_MODEL`, `LAB11_PERFORMANCE_MODEL`.

## 5. Корисні експерименти (CLI, без Web UI)

```bash
# один прогін, слід спроб і токени
go run ./week6/Day11_Dynamic_Workflows_Multi_Critic/labs11/solution -offline -task prorate_refund

# вузький бюджет: має завершитись помилкою «вичерпано бюджет спроб»
go run ./week6/Day11_Dynamic_Workflows_Multi_Critic/labs11/solution -task parse_amount -max-attempts 1

# eval по всіх завданнях: таблиця «прийнято / спроб / holdout / токенів»
task week6:day11:solution:eval LAB_OFFLINE=1

# вартість за власним тарифом ($ за 1M токенів)
go run ./week6/Day11_Dynamic_Workflows_Multi_Critic/labs11/solution -task validate_iban -price-in 0.3 -price-out 1.2

# база для регресій: записати, потім порівнювати
go run ./week6/Day11_Dynamic_Workflows_Multi_Critic/labs11/solution -eval -baseline base.json -write-baseline
go run ./week6/Day11_Dynamic_Workflows_Multi_Critic/labs11/solution -eval -baseline base.json
```

## 6. Що вважати «пройшло»

1. Прогін завершується без паніки, у Events видно `maker`, рішення gate і (після зеленого gate) вердикти критиків.
2. Прийнятий код проходить **holdout** (`holdout: так`); рядок «прийнято циклом, але хибне на holdout» дорівнює 0.
3. Токени пораховано за `UsageMetadata`; офлайн вони оцінкові й так підписані.
4. `task week6:day11:solution:eval LAB_OFFLINE=1` дає 3 з 3 на holdout.

Прогін на реальній моделі недетермінований: повторіть його кілька разів, перш ніж
робити висновок із невеликої різниці.
